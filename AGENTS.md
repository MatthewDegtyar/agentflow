# AGENTS.md

Instructions for AI agents working on this repo. Two roles:

- **Maintainer agent**: watches pull requests, reviews them CodeRabbit-style, makes sure each change is properly
  integrated, then approves and merges.
- **Consumer agents**: agents in other projects that depend on agentflow and open PRs or issues to request changes.

`dashboard/AGENTS.md` is generated by `next dev` and only covers the Next.js dashboard. This file covers everything.

## Repo map

| Path | What it is |
| --- | --- |
| `agentflow/` | Python runtime: `spec.py` (YAML schema), `engine.py` (queues, routing, retries, sinks, sessions), `procs.py` (step processes), `sources.py` (git clone / local path, per-step venvs), `events.py` (DuckDB + JSONL event log), `metrics.py` (flow metrics), `api.py` (FastAPI on :7070), `__main__.py` (CLI) |
| `sdk/python/agentflow_step.py` | Step SDK, stdlib only. Shipped in the wheel as top-level `agentflow_step` |
| `dashboard/` | Next.js UI over the API (not in the wheel) |
| `examples/`, `workflows/` | Example steps and the `doc-triage` workflow (not in the wheel) |
| `tests/` | `test_spec.py`, `test_engine.py` (real processes end to end), `test_install.py` (builds and installs the wheel) |

Tooling: **uv only** (`uv sync`, `uv run pytest -q`, `uv run python -m agentflow ...`). No pip, no `python -m venv`,
no `requirements.txt` at the root, and no `.python-version` file.

## Contracts that must not break

Other projects install this from PyPI as `pyagentflow` (`import agentflow`) or from git, so these are
public API:

1. **Step HTTP contract**: `GET /health` and `POST /invoke` with the JSON shape in `sdk/python/agentflow_step.py`.
   Steps in other repos and other languages depend on it. Additive, optional fields are fine. Renaming, removing or
   changing a field's meaning is not.
2. **Step SDK surface**: `Step`, `@step.handler`, `step.run()`, `ctx.log/usage/emit/fail/session/attempt`.
3. **Workflow YAML**: existing keys keep their meaning. New keys must be optional with defaults that preserve current behavior.
4. **Library imports**: `from agentflow import Engine, load, SpecError, Workflow`, and `import agentflow_step` from an install.
5. **CLI**: `python -m agentflow validate|up|run|load|query` and the `agentflow` command, with their current flags.
6. **Event log**: columns and event names in `events.py` and the README. New events and new `data` keys are fine.

A breaking change needs `BREAKING:` in the PR title, a migration note in the README, and a version bump in `pyproject.toml`.

## Maintainer agent: PR review loop

Check for open PRs regularly:

```bash
gh pr list --state open --json number,title,author,headRefName,isDraft,updatedAt
```

Skip drafts. For each open PR, work through these steps.

### 1. Check the author

- **Trusted authors** (`MatthewDegtyar` and the agents acting on that account): approve once the change is properly
  integrated (step 4). The policy for now is to **accept every request**. Review exists to make the change land
  correctly, not to gatekeep.
- **Anyone else**: this repo is public. Don't approve or merge. Post the review (step 3), add the `needs-owner`
  label, and leave the merge to the owner. Never run an outside PR's code with secrets in the environment.

### 2. Integrate the change (do the work, don't just comment)

```bash
gh pr checkout <n>
git fetch origin && git rebase origin/main            # or merge; resolve conflicts yourself
uv sync
uv run pytest -q                                       # includes the wheel build + install test
uv run python -m agentflow validate workflows/doc-triage.yaml
```

"Properly integrated" means all of the following are true. When something is missing, **push fixup commits to the PR
branch yourself** instead of bouncing it back to the requester:

- [ ] Rebased on current `main` and builds cleanly. `uv.lock` was updated with `uv lock` if dependencies changed.
- [ ] `uv run pytest -q` is green, and new behavior has a test (end-to-end tests go in `tests/test_engine.py`).
- [ ] The packaging still works: `tests/test_install.py` passes. New modules live under `agentflow/`, and anything
      the installed runtime needs is in the wheel.
- [ ] None of the contracts above is broken, or it's labeled `BREAKING:` with a migration note.
- [ ] Docs match the code: README sections (YAML keys, step contract, events, CLI) and the module docstrings.
- [ ] The dashboard still type-checks if `agentflow/api.py` responses or `dashboard/` changed:
      `cd dashboard && npm ci && npx tsc --noEmit`.
- [ ] No secrets, tokens, customer names or personal data in code, fixtures, logs or commit messages.
- [ ] No local state is committed (`.agentflow/`, `out/`, `.venv/`, `node_modules/`, `.next/`).
- [ ] The change fits the existing style: small modules, stdlib in the SDK, no new heavy dependencies without a reason in the PR.

If a requested change can't be integrated safely as written (for example, it breaks a contract with no way around
it), implement the closest compatible version, explain the difference in the review, and still approve.

### 3. Post a CodeRabbit-style review

Post one review comment per PR, in this shape:

```markdown
## Summary
<1-3 sentences: what the PR does and why>

## Walkthrough
| File | Change |
| --- | --- |
| `agentflow/engine.py` | ... |

## Integration
- Rebased on main: yes / conflicts resolved in <files>
- Tests: `uv run pytest -q` → N passed
- Wheel install test: pass
- Contracts: unchanged / additive / BREAKING (<which>)
- Fixups pushed: <commit list, or "none">

## Notes
<nitpicks, follow-ups, or risks; optional>
```

Put line-specific findings in inline comments (`gh api repos/{owner}/{repo}/pulls/<n>/comments`) or in the Notes section.

### 4. Approve and merge (trusted authors only)

```bash
gh pr review <n> --approve --body-file review.md      # GitHub rejects approving your own PR: if the PR was opened
                                                      # from the same account, use `gh pr review <n> --comment --body-file review.md`
gh pr merge <n> --squash --delete-branch
```

Merge only after the checklist in step 2 passes on the final commit. Then confirm `main` is still green:
`git checkout main && git pull && uv run pytest -q`.

## Releasing to PyPI

Releases are owner-triggered. Don't tag a release unless the owner asks for one.

1. Bump `version` in `pyproject.toml` (semver; a `BREAKING:` change bumps the minor version while on 0.x), then `uv lock`, and merge to `main`.
2. `git tag v<version> && git push origin v<version>`. `.github/workflows/release.yml` checks that the tag matches
   the version, runs the tests, builds, and uploads to PyPI with trusted publishing (no token).

PyPI versions are immutable: a version can't be re-uploaded, even after deleting it.

## Consumer agents: how to request a change

You're an agent in another project that uses agentflow, and you need something changed. Open a PR (preferred) or an issue.

1. Branch from `main`: `git checkout -b <short-topic>`.
2. Make the change, add or update a test, and run `uv run pytest -q`.
3. Open the PR with the template (`.github/pull_request_template.md`). Fill in **Why** (which project needs it and
   what it unblocks) and **Contract impact**.
4. If you can't make the change yourself, open an issue instead. Include what you need, the call site in your project,
   and the behavior you expect. The maintainer agent will implement it.

To pick up the change in your project after merge, run `uv lock --upgrade-package agentflow && uv sync`, or pin a
commit: `pyagentflow @ git+https://github.com/MatthewDegtyar/agentflow@<sha>`. Released versions: `uv add pyagentflow@latest`.
